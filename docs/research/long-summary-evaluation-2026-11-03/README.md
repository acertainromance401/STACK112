# 장문 판례 요약 평가

## 실험 전 고정한 범위

기존 세 판례 A(2024므16033, 16040), B(97므1486, 1493), C(2026으552)를 사용한다. [원문과 출처 한계](../datasets/family-law-retrieval-v1/README.md)는 기존 자료와 동일하다. 문서별 6개, 총 18개 핵심 항목을 [gold.json](gold.json)에 생성 출력 관찰 전에 고정한다. 법률 전문가의 독립 검수 정답이 아니라 원문 대조 AI 예비평가다.

| 조건 | 생성 입력 구성 |
| --- | --- |
| F · fields | 기존 JudgmentParser의 판시사항·판결/결정요지·참조조문을 기존 앱 요약 필드에 전달 |
| K · keyword | 현재 판례 내부에서 키워드 검색으로 세 관점의 최상위 청크를 각각 선택 |
| S · semantic | 같은 문서·질문에서 E5 코사인 검색으로 선택. 키워드 점수·대체 없음 |
| H · hybrid | 같은 문서·질문에서 기존 키워드 + E5 RRF로 선택 |

F는 **현행 프롬프트·예산을 사용하는 구조화 필드 기준 조건**이며, UI의 최종 카드나 전체 앱 경로를 그대로 재현한 조건은 아니다. 다른 판례 참고는 모든 조건에서 제외하여 현재 판례의 요약에 집중한다. K·S·H는 다른 참고 판례를 검색한 앞선 B1·S·H와 구별되는 **문서 내부 검색 조건**이다.

세 고정 질문은 `핵심 쟁점 판시사항`, `판단 이유 법리 원칙 예외`, `주문 결론 파기 환송 기각`이다. 정답 항목·법률 해설은 모델에 제공하지 않는다. 청킹과 점수·순위 계산은 앱 검색기를 재사용하며, 문서 내부 검색은 현재 문서를 제외하지 않는다. 각 질문의 최상위 청크를 쟁점·판결·포인트 필드에 순서대로 넣는다. 중복 청크도 그대로 기록한다.

생성기는 실제 Llama-3.2-1B-Instruct Q4_K_M이다. 네 조건 모두 기존 요약 템플릿·chat wrapper·필드 제한 `[96,64,48,32,16,8]`·토큰 검증·실행 설정을 공유한다. 실제 선택된 입력은 짧아질 수 있으며 모든 원시 프롬프트를 보존한다. 모델의 원시 출력을 평가하고 UI 후처리·정규화·규칙 기반 폴백을 생성 성공으로 집계하지 않는다.

생성 모델은 한 번 로드하고 로드 시간을 별도 기록한다. S·H는 문서·조건마다 새 E5 provider를 사용하므로 근거 선택 시간에 초기 로드·문서 벡터 구축이 포함되며, 같은 셀의 세 질문 사이에서는 문서 벡터를 재사용한다. 이는 warm 검색 지연 순위 실험이 아니다. 문서 순서대로 조건 순서를 회전하며 셀당 1회, 총 12회 생성한다. 시뮬레이터 기능·품질 파일럿이며 실기기 성능이나 통계적 우월성을 뜻하지 않는다.

## 평가 정의

- **입력 핵심 포함률:** 실제 전달 프롬프트가 핵심 항목을 충분히 포함한 정도. `full=1`, `partial=0.5`, `absent=0`.
- **출력 핵심 포함률:** 생성 요약이 원문 핵심 항목을 올바르게 포함한 정도. `full=1`, `partial=0.5`, `absent/contradicted=0`.
- **원문 근거성:** 생성된 실질 주장 중 전체 원문이 지지하는 주장 비율. 주장 0개면 미정의이며 100%로 채우지 않는다.
- **입력 근거성:** 같은 주장 중 실제 전달 입력이 지지하는 비율. 원문과 입력 지지를 구별한다.
- **모순·근거 없는 주장:** 원문과 반대인 주장과 원문으로 지지할 수 없는 주장을 각각 집계한다. 오류 없음이 완전성이나 법률적 정확성을 뜻하지 않는다.
- **결론 보존:** 각 문서의 실제 주문 핵심 항목이 올바르게 포함되었는지 별도로 기록한다.
- **비용:** 근거 선택·프롬프트 준비, 원시 생성, 총 요청 벽시계 시간을 분리한다. 생성 모델 최초 로드는 요청 밖이다.

문장 표현 일치만으로 점수를 자동 부여하지 않는다. 항목별 판단 이유와 실제 출력 구절, 주장별 원문 지지 구절을 공개한다. 전문가 정확도·독립 검수자 간 일치도·ROUGE/BERTScore를 측정한 것으로 표시하지 않는다.
