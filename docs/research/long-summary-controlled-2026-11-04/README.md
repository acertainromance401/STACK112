# 판례 C 문자 제한·생성 통제 실험: 사전 계획

## 질문과 범위

기존 [장문 요약 파일럿](../long-summary-evaluation-2026-11-03/RESULTS.md)의
입력 손실과 확률적 생성 변동을 분리한다. **평가 경로에서만** 문자 제한을 제거하며
앱의 기본 컨텍스트·문자 제한·출력 예산·샘플링은 바꾸지 않는다.
사용자가 승인한 범위는 판례 C 한 건, 실제 생성 40회다. 다른 판례로 확장하지 않는다.

- 원문: 기존 데이터셋 `sc-2026eu552`, 2026으552.
- 정답 항목: 이전 생성 전에 확정한 C1–C6 여섯 항목을 그대로 재사용한다.
  원본은 [gold.json](../long-summary-evaluation-2026-11-03/gold.json).
- 외부 판례, OCR, UI 정규화·후처리, 규칙 기반 fallback은 사용하지 않는다.
- 판례 수는 **n=1**이다. 40회는 40개의 독립 법률 문제나 정확도 분모가 아니다.

## 2 × 4 × 5 설계

| 차원 | 조건 |
|---|---|
| 문자 정책 | capped: 기존 준비 함수와 96자 시작 정책 / uncapped: 네 필드 전체 |
| 입력 구성 | F: 파서 쟁점·판결·법령 / K: 키워드 / S: E5 단독 / H: RRF 결합 |
| 생성 | greedy 두 번 / 확률적 seed 42, 43, 44 각각 한 번 |

K/S/H는 기존과 동일한 원문 내부 320자/64자 중첩 청크와 세 가지 일반 질의를 사용한다.
각 질의의 첫 청크를 쟁점·판결·시험포인트 필드에 배정하고 중복도 그대로 유지한다.
같은 구성에서 선택은 한 번만 수행하여 두 문자 정책과 다섯 생성에 재사용한다.
따라서 두 정책의 차이는 선택된 원문이나 검색 재실행 변동이 아니라 전달 문자 제한이다.
**uncapped는 선택된 필드 전체이며, 원문 전체 투입 또는 검색 없는 전문 요약을 뜻하지 않는다.**

초기 실험 전용 컨텍스트는 8,192토큰, 모든 조건의 출력 상한은 동일하게 128토큰이다.
실제 토크나이저로 여덟 프롬프트를 사전 검증한다. 입력 + 출력 128 + 여유 8토큰이
공통 컨텍스트에 맞지 않으면 **생성하지 않고 실패**한다. 입력 토큰을 조용히 자르지 않는다.
문자 제한만으로 발생한 차이를 보려고 capped도 이 확대 컨텍스트를 사용하므로,
이전 512토큰 이하 런타임과 이번 capped 결과의 차이를 문자 정책의 효과로 해석하지 않는다.
출력 예산 자체의 효과는 이번 실험의 조작 변수가 아니다.

두 정책 모두 같은 요약 지시·필드 표지·Llama 3 래퍼를 사용한다.
확률적 생성은 기존 top-k 40, top-p 0.9, temperature 0.4,
repetition penalty 1.1/최근 64토큰을 유지하고 자동 seed만 명시적 seed로 바꾼다.
Greedy는 같은 repetition penalty 후 argmax이며, 온도·top-k·top-p·분포 샘플러는 사용하지 않는다.
기존 생성 루프의 sample/accept 호출 순서도 바꾸지 않는다.
각 요청에서 KV 메모리를 초기화하고 평가 샘플러를 새로 만들고 reset한다.
분포 샘플러가 실제 사용한 seed를 런타임 API로 확인한다.

먼저 greedy 1회씩 8조건, greedy 2회차, seed 42, 43, 44 순으로 실행하며
각 라운드의 조건 시작 위치를 한 칸씩 회전한다. 완료한 각 출력을 원자적으로 저장한다.
기존 manifest/출력 파일 덮어쓰기는 거부한다. 재실행이 필요하면 실패 로그와 별도 배치를 남긴다.

## 사전 고정과 사후 분석

생성 전 `raw/manifest.json`에 실제 원문·선택 청크·APICase 필드·원시/래핑 프롬프트,
입력 SHA-256·토큰 수·모델 SHA-256·환경·선택 시간을 저장한다.
계획, 이전 정답 파일, manifest, 측정에 사용한 Swift 소스·패키지 고정 파일의 해시를
생성 출력 확인 전에 기록한다.

사후에는 다음을 구분하여 표·CSV·matplotlib PNG/SVG로 제시한다.

1. **재현성:** 여덟 greedy 쌍의 실제 출력 문자열과 해시 일치 여부.
2. **품질:** C1–C6 입력/출력 coverage(full=1, partial=0.5, absent/contradicted=0),
   결론 보존, 명시적 반대 진술, 출력 형식 성공.
3. **변동:** seed 세 개의 구성별 평균과 표본 표준편차(ddof=1),
   동일 seed의 uncapped − capped 차이. Greedy 중복을 확률적 표본에 합치지 않는다.
4. **혼동 통제:** 실제 전달 프롬프트 해시로 정책·구성을 가로질러 동일 입력을 묶고,
   동일 decoder/seed 조건의 출력도 비교한다. 입력이 같으면 검색 우열 근거로 삼지 않는다.
5. **비용:** 입력/실제 생성 토큰, stop reason, 실제 생성 시간.
   검색 선택은 한 번 수행한 공통 전처리 비용으로 별도 표시하고 5회 반복 계측인 척하지 않는다.
6. **해석 한계:** source-bounded AI 예비 검수이며 독립 법률 전문가 검증이 아니다.
   한 판례·세 seed로 통계적 유의성이나 일반적 우월성을 주장하지 않는다.

실행기는 [ControlledSummaryEvaluationTests.swift](../../../code/ios/AISYSAppTests/ControlledSummaryEvaluationTests.swift).
이 계획은 새 출력 확인 전에 작성했으며 결과 보고서는 별도로 보존한다.
