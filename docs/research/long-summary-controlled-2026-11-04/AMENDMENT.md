# 실행 범위 변경: 40회에서 24회로 축소

## 변경 사유와 시점

2026-11-04 사용자가 실행 시간을 이유로 약 20회로 줄일 수 있는지 요청했다.
17개 완료 체크포인트를 확인한 후 **24회 균형 설계**를 제안했고 사용자가 선택했다.
seed 42의 출력 내용이나 품질 점수를 보고 실행 범위를 선택한 것이 아니다.
처음 작성한 [40회 사전 계획](README.md)과 해시는 수정하지 않고 보존한다.

## 최종 분석 설계

| 차원 | 유지 조건 |
|---|---|
| 문자 정책 | capped / uncapped |
| 입력 구성 | F / K / S / H |
| 생성 | greedy 두 번 + 고정 seed 42 한 번 |
| 완료 출력 | **2 × 4 × 3 = 24개** |

- 모든 조건에 같은 입력 선택·요약 템플릿·래퍼·8,192 컨텍스트·128 출력 예산을 유지한다.
- seed 43/44는 평가하지 않는다. 단일 seed 점수는 다중 seed 평균이 아니다.
- seed 간 표준편차·변동·신뢰구간을 계산하거나 주장하지 않는다.
- greedy 쌍의 재현성, greedy 조건 간 점수, **seed 42에서의** 정책별 차이를 구분한다.
- K/H의 입력이 같은 사실도 그대로 표시한다.
- 검수 기준과 C1–C6 정답은 바꾸지 않는다. 불리한 완료 출력을 골라 버리지 않는다.

## 실행·보존 방식

이미 실행 중인 바이너리는 원래의 40회 루프이므로, 24번째 원자적 체크포인트가
저장되면 해당 전용 시뮬레이터의 앱만 종료한다. 따라서 원래 XCTest 실행은
**사용자 요청에 따른 의도적 중단**이며 40회 테스트 통과로 표시하지 않는다.
종료 신호가 전달되기 전 다음 요청이 시작되었을 가능성도 있으므로,
완료 출력 수와 시작된 요청 수를 동일하다고 단정하지 않는다.

24개 원시 체크포인트와 최초 manifest를 먼저 내보내고, 그 체크포인트에서
분석용 report를 조립한다. 원래 바이너리가 최종 report에만 기록하려던 본실험
모델 로딩 시간은 관측되지 않았으므로 **null/미측정**으로 남긴다.
사전 검증의 모델 로딩 시간을 대신 넣거나 0초로 바꾸지 않는다.

측정에 사용한 원래 Swift 실행기 소스는 `measured/`에 해시와 함께 보존한다.
재현용 작업공간 실행기는 같은 순서의 첫 24회만 수행하도록 줄인다.
두 실행기의 차이는 seed 43/44와 완료 개수이며, 모델·입력·디코더는 동일하다.
최종 결과는 별도 결과 보고서에 기록한다.
